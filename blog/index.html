SOLVING WITH UNKNOWN PARAMETERS7 POSTS · INTERACTIVE

From school algorithms to real-world unknowns

Seven interactive posts on the gap between textbook problem solving and production decision systems: hidden parameters, costly exploration, probabilistic signals, delayed rewards, and policies you can edit instead of merely train.

A side project of the WPO-Gym / EDP research. School gives you Dijkstra, sorting, and TSP with all the numbers printed on the page. Reality hides the numbers and charges you to discover them. Each post is a static HTML file: read, then play. Live LLM calls are optional; recorded traces keep the series usable offline.
Objects you'll meet
  • Bandit: choose arm a_t, observe noisy reward r_t, minimize regret against the best hidden mean.
  • Combinatorial bandit: choose a structured action such as a path, tour, or slate, then update shared hidden parameters.
  • OPRO: ask an LLM to propose the next candidate x_t from a history of scored candidates.
  • GAM / EDP: map observed signals through named curves g_j(x_j), estimate latent parameters, then run a normal solver.
  • WPO: the capstone where reward is delayed, noisy, page-level, and hard to attribute.

The ladder

level 0 · post 1
Pick from unknown options
The smallest real-world problem: choose among hidden options, observe noisy reward, pay regret while learning. This is the multi-armed bandit.
level 1 example · post 2
Sorting numbers you cannot read
A classical algorithm becomes a Gym problem: hidden values, noisy comparisons, estimated parameters, and a solver acting before it has full information.
level 1 example · post 3
Shortest path when the edge weights are hidden
Dijkstra still works, but only on estimates. Walk paths, reveal edge samples, update the model, and see why decomposed feedback matters.
level 1 example · post 4
TSP when the distances are hidden
A factorial action space is survivable only if observations update shared parameters. The solver is still 2-opt; the environment is now uncertain.
level 1 bridge · shared Gym
Run algorithms when the inputs are missing
One in-browser Gym contract powers sort, shortest path, and TSP: reset, observe, act, step, learn. The algorithm is old; the feedback loop is the new thing.
level 2 · post 5
Can an LLM explore?
OPRO as the foundation before EDP: an LLM proposes candidates from score history. Try linear regression, TSP, and a constrained linear objective with recorded traces or your own OpenAI-compatible API key.
level 3 · post 6
Human-like priors as executable policy
EDP generalizes the idea: estimate latent parameters with named GAM curves over signals, then run the solver. WPO is one instance, not the whole idea.
levels 4-5 · post 7 · finale
Production feedback is hostile; WPO is the capstone
Delayed, noisy, page-level reward changes the game. Tuned bandits can tie on regret, but EDP's edge is cold-start, auditability, editability, and readable serving code.

The arc, in one sentence

You were taught to solve problems after the inputs are known; production asks you to solve while learning the inputs, under cost, noise, delay, and missing attribution. The series walks from bandit exploration to combinatorial Gym interfaces, then to OPRO and EDP: policies that use LLM/human reasoning to start with a better guess and keep that guess editable.
