Can an LLM explore?

Bandits explore by choosing an action, observing a reward, and updating a posterior. OPRO asks a stranger question: can a language model read only candidate-score history and propose the next thing to try?

This is the missing step before EDP. EDP is not just "ask an LLM for a policy." It works because the policy has a representation the LLM can edit. OPRO is the simpler foundation: give the model prior attempts and scores, ask it to propose a better candidate, then evaluate that candidate in a black-box environment.

Live calls are optional. Paste an OpenAI-compatible API key if you want the page to call your provider. Without a key, the widget uses deterministic recorded suggestions so the post remains offline and static.

Act 1 — The interface

Every example below exposes the same loop: a hidden objective scores a candidate; the history becomes the prompt; the LLM proposes the next candidate as JSON; the page evaluates it. The LLM is not in the solver path yet. It is imitating an optimizer.

history = [(candidate_1, score_1), ...]
prompt  = "Propose one better candidate as JSON"
next    = llm.complete_json(prompt, history)
score   = hidden_objective(next)
history.append((next, score))
OPRO object
  • Unknown: black-box objective F(x); you can score candidates but not inspect gradients.
  • Action: propose a candidate string/JSON object x_t.
  • Feedback: observe scalar score y_t = F(x_t), often lower is better.
  • Prompt state: history H_t = {(x_i, y_i)}, sorted or summarized for the LLM.
  • Risk: score-only feedback gives no local gradient, no uncertainty estimate, and weak validity guarantees.

Act 2 — What this teaches

OPRO can be surprisingly competent when candidates are short and scores are informative. It can also get stuck, hallucinate invalid JSON, or make locally plausible moves that do not improve the hidden objective. That fragility is the point: score-only search is a weak feedback channel.

This is why EDP comes next. Instead of asking the model to optimize arbitrary strings from score history, give it a representation whose fields mean something: curves, weights, signals, slots, constraints. Then the LLM can use human-like reasoning to produce a structured prior or edit, while the Gym environment still supplies the empirical score.
